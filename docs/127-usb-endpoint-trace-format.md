# USB endpoint trace result correction (NEO-97)

3 October 2026, Pacific/Auckland. Patch 0024 corrects the USB gadget endpoint
trace formatter to print the operation's recorded result. It has passed
actual-source native/ARM32 formatting regressions and full ARM UDC-core
compilation. The running diagnostic.17 image is unchanged; image integration
and live trace qualification remain pending.

## Defect and correction

[Report 125](125-traced-rtc-wake-usb-failure.md) recorded endpoint-disable lines
ending in `--> 1` even though their stored endpoint state was disabled. In the
pinned `drivers/usb/gadget/udc/trace.h`, `udc_log_ep` stores the operation result
in `__entry->ret` but its `TP_printk` expression uses bare `ret`.

The event printer generated by `include/trace/trace_events.h` also declares
`int ret`, assigning it the result of `trace_raw_output_prep()`. The expression
therefore prints the printer's status rather than the endpoint operation result.
The saved live `usb_ep_disable/format` confirms the same expression on the board.

[`0024-usb-gadget-endpoint-trace-result.patch`](../kernel/patches/0024-usb-gadget-endpoint-trace-result.patch)
changes only that expression to `__entry->ret`. Event storage, endpoint state,
control flow and USB behavior remain unchanged. Other gadget/request event
classes already print their recorded return fields correctly. Remove this
patch once the selected upstream source has the equivalent correction.

The recorder also saves `endpoint_return_text_trusted`. It is true only when
both live endpoint enable/disable formats expose the stored result field and
print `REC->ret` as the final argument. Old or unfamiliar formats remain usable
for other metadata but receive `false`; their trailing arrow value is not an
operation-status proof. This does not rewrite any historical result.

## Repeatable validation

```sh
task test:udc-trace
task check:udc-driver
task check
```

The source check verifies the locked Linux archive, applies the patch to an
isolated header, extracts its actual `TP_printk` expression and executes it
against synthetic records. Its 252 scenarios vary the stored success/error
code independently from printer status, endpoint name, claimed state and
enabled state. The whole rendered line must match, including other fields.

The candidate passes natively and under ARM32 emulation. Three negative
controls fail as expected: original bare `ret`, constant success and reversed
error sign. The complete patched ARM `drivers/usb/gadget/udc/core.o` also builds
using the project's full patch queue, with SHA-256
`f115e6af99611aec12d7a193a556533be8fe597245cb39160c6106a6c5bf1366`.

Evidence: `.local/build/udc-trace-tests/compile-evidence.json`;
log: `.local/build/udc-driver.log`. Patch SHA-256:
`36913d794b710ade3fb4788da4ec7fe782c5dd193705ef1f48756ebf764313c1`.

The recorder's 16 tests pass, including old/missing/malformed formatter
classification. `task check` passes 13 runtime tests and 453 tooling tests
(one existing optional skip), the compiled selector/mount-guard tests and shell
lint. Full log: `.local/neo97-check.log`. `task build` now runs this source check
before building the kernel.

No live endpoint operation or USB reconnect is exercised by these source tests.
The correction improves diagnostic accuracy; it does not fix NEO-95's resume
failure or establish a performance or power saving. The next image must carry
the patch, and its live endpoint formats/results must be checked before marking
hardware qualification complete. The recorder source change also requires a
matching new rehearsal before any future actual sleep submission.
